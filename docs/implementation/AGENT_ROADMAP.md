# Agent Expansion Roadmap

Status: **approved working track** (2026-08-09, user decision). This is a parallel expansion track alongside the platform roadmap in [ROADMAP_STATUS.md](ROADMAP_STATUS.md) — it does not renumber or replace those phases. The guiding rule, in the user's words: single-agent loop first, phase by phase, each phase adding one real capability. **No multi-agent until the single loop is reliably doing Plan → Build → Inspect → Fix.**

## Architecture decisions (A1, load-bearing)

- **The loop lives in the gateway** (`services/gateway/internal/agent`), reusing the existing `provider.Provider` seam — the agent inherits every provider the stack gains in platform Phase 4/5 for free.
- **Statuses are the contract**: `planning → executing → inspecting → fixing → completed | failed`. The /chat five-state UI maps onto them without rework (working card = live run card). Later phases add step _kinds_, never a new lifecycle.
- **HTTP surface**: `POST /v1/agent/runs` (create, auth + rate limited), `GET /v1/agent/runs/{id}` (poll snapshot, auth), `POST /v1/agent/runs/{id}/cancel` (real cancellation via context). Polling, not SSE — smallest thing that works; SSE is an A5 refinement.
- **Runs are in-memory and ephemeral** — the platform's database phase is still blocked (WSL2); when it lands, runs gain persistence without API changes.
- **A2 tools execute in a per-run workspace inside the container** (`AGENT_WORKSPACE_DIR`, default temp), not on the caller's machine. Path safety is the one security boundary: `Workspace.resolve` rejects absolute paths (cross-platform: `filepath.IsAbs`, leading separators, and volume names), rejects any `..` component, and re-verifies containment with `filepath.Rel`. Only 5 read/write tools exist — no delete/install/git until the approval system (A8) lands. Generated files are served at `GET .../files/{path}` as `text/plain` with `nosniff` and previewed only in a sandboxed iframe, so agent-authored markup never executes in the gateway's origin. (A2 shipped with only 5 read/write file tools; the terminal arrived in A3 and its sensitive-command gating in A8.)
- **Tools use a text JSON protocol, not native tool-calling** — the provider seam is plain chat, and a text protocol is portable across every backend in the free stack (which each have different native formats). Model calls per run are bounded: ≤5 plan steps × ≤6 tool calls, plus one fix loop.
- **A3 terminal (`run_command`)** runs `sh -c` (Linux/prod) or `cmd /c` (Windows/dev) with cwd = workspace, a 60s timeout, and 8 KB output cap. Sensitive categories (install/delete/git/network-fetch/privilege — classified by `commandCategory`) are no longer hard-blocked: as of A8 they pause for the user's approval instead. **Runtime caveat:** the production image is `alpine:3.20` (BusyBox `sh` + coreutils only); node/npm/go/python are not installed, so JS/Go build+test commands won't run in prod until a language-runtime is added to the image. The mechanism is complete and works for shell/coreutils commands.
- **A8 approval gate** lives in the engine (`runTool` → `requestApproval`), the only place with both the run context and a user channel. A sensitive `run_command` sets `Run.Pending` + status `awaiting_approval` and blocks on a per-run `decision` channel (ctx-cancellable). `Decide(allow, remember)` answers; "always allow" adds the category to a per-run allow-set so it won't re-prompt. Deny returns a "DENIED by the user" tool result the model adapts to. `commandCategory` (in executor.go) is the classifier; `RunCommand` itself no longer gates — that decision is centralized in the engine.
- **Rate-limit resilience**: `chatMessages` retries on an upstream `CodeRateLimited` with a ctx-aware backoff schedule (default 5/12/20/30s, overridable per engine for tests). A single agent run bursts many calls and would otherwise die on a free-tier per-minute cap. This is a stopgap for true multi-provider failover (platform Phase 4), which will spread calls across Gemini/Groq/SambaNova/Cloudflare instead of waiting.
- **Tool-activity log**: each run carries a capped `Log` of tool actions (verb + key arg), surfaced live in the /chat working card. Partial delivery of A5 (task events).
